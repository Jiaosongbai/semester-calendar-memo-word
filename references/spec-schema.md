# 输入数据规范

生成器只接受经过核对的 JSON 数据。日期统一写成 `YYYY-MM-DD`，不得根据常识补齐缺失日期。

## 顶层字段

| 字段 | 必填 | 含义 |
|---|---:|---|
| `title` | 是 | Word 主标题 |
| `subtitle` | 否 | 标题下方灰色副标题 |
| `sections` | 是 | 要生成的学期或短学期 |
| `statutory_holidays` | 否 | 政府正式公布的放假区间 |
| `calendar_day_markers` | 否 | 校历只标出节日名称、但未确认放假的单日标记 |
| `school_breaks` | 否 | 学校自行安排的寒假、暑假等假期 |
| `activities` | 否 | 需要用 Word 脚注展示的校园活动 |
| `source_note` | 否 | 来源及信息边界说明 |

## 学期 `sections`

每项包含：

- `name`：学期名称。
- `start`：第 1 周星期一。
- `weeks`：本部分总周数，1–25。
- `exam_from_week`：可选；从第几周开始标注“考试周”。
- `info`：可选；报到注册、行课、考试、寒暑假等摘要。

若缺少第 1 周星期一或总周数，不生成并先询问用户。不要把假期长度当作教学周数。

## 三类日期

- `statutory_holidays`：每项为 `name`、`start`、`end`。仅在政府正式通知确认后填写，区间内每天标为“法定放假”。调休上班日写入对应学期的 `info` 或来源说明，不伪装成假日。
- `calendar_day_markers`：每项为 `name`、`date`。输出为“校历标记”，不得扩展成连续假期。
- `school_breaks`：每项为 `name`、`start`、`end`。输出为“学校假期”，与法定节假日分开。

同一天可以同时具有多种标记，生成器会分别保留。

## 活动 `activities`

每项包含：

- `text`：脚注全文。
- `precision`：`day`、`month` 或 `range`。
- `anchor_date`：脚注在版面上的锚点日期。
- `duration_rank`：可选，短活动用 `1`，长跨度活动用较大的整数。

`day` 的 `anchor_date` 必须是已确认的实际日期。`month` 或日期边界不完整的 `range`，由整理数据的模型在相应月份内选择版面锚点；脚注原文必须保留真实精度，不得把锚点描述为开始日期。较长、较不确定的活动应使用更晚的锚点。

## 脚注容量

三周一页的已验证空白版式，每页最多容纳 16 行渲染后的 8 磅脚注文字。这里按换行后的实际行数计算，不按活动条数计算。预计超过上限时，应调整月度或范围活动的 `anchor_date`，将其分散到后页；不得缩小字号或突破页边距。

## 兼容性边界

输出仅为 `.docx`。生成器不创建 Excel、每日视图、课程表、提醒、日历订阅或手机界面。
